# 人工评审量表（iteration-4 新增）

> 为什么需要它：`grade_v4.py` 只能判"结构对不对"（文件在不在、门禁过不过、链接死不死）。
> 但真正决定这套体系好不好用的是**写出来的东西有没有用** —— 这部分必须人看。
> 每个运行目录（`with_skill/`、`without_skill/`）都按下面 3 个维度各打 0–2 分，共 6 分。

## 打分办法

| 分值 | 含义 |
|---|---|
| **2** | 好：下一个人/AI 看完能直接用，不用再翻聊天记录 |
| **1** | 勉强：信息在，但要说清楚还得再问一轮 |
| **0** | 没用：复述了 diff / 空话 / 关键信息缺失 |

三个维度：

### D1 日志是否"记得住重点"（0–2）

看它写的日志里有没有这四样：**改了什么**（具体文件/函数）、**为什么这么改**（业务或技术动因）、
**怎么证明是对的**（测试/验证方式）、**还留了什么坑**（遗留风险/没覆盖的路径）。

- 2 = 四样齐且具体（提到函数名、边界条件）
- 1 = 缺一两样，或写得很泛（"优化了逻辑"）
- 0 = 基本是 diff 复述，或只有一句标题

### D2 知识沉淀是否"可复用"（0–2）

看它有没有把**会重复踩的结论**沉淀成知识，且写成了"下次遇到能照着做"的形态。

- 2 = 沉淀了，且写清了触发条件（什么情况下会踩）+ 处置办法；分类/命名规范
- 1 = 沉淀了但像日志的复制粘贴，没有"下次怎么用"
- 0 = 该沉淀没沉淀（或把一次性细节也硬塞成知识）

### D3 是否正确"尊重既有约定与事实"（0–2）

看它有没有先看项目里已有的规矩（`AGENTS.md`、既有索引、既有命名），再做动作；
有没有**改坏/丢掉**别人的东西（历史日志内容、用户手写的段落）。

- 2 = 先读约定再动手；动过的历史文件有说明；无内容丢失
- 1 = 大体对，但有小越界（如自作主张改了用户手写段落）
- 0 = 无视既有约定，或造成内容丢失

## 记录格式（每个 run 目录下建 `manual_review.md`）

```markdown
# 人工评审 — <用例>/<配置>

| 维度 | 分 | 依据（一句话，附文件:行） |
|---|---|---|
| D1 日志记得住重点 | /2 | |
| D2 知识可复用 | /2 | |
| D3 尊重既有约定与事实 | /2 | |
| **合计** | /6 | |

评审人：      日期：
```
